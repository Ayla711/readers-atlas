## 1. 机器已经查过的，人不用再查

导入脚本（`tools/import_pack.py`）和 `node tools/validate.js` 已经保证：原文和古登堡逐字一致；高亮词在文本里；书和地点都存在；有版权的书只有场景说明；坐标落在该国的某个一级区；照片许可可用；id 不冲突；作者拼法一致。审核页上不重复这些。

## 2. 人要判断的（每条看这六点）

**摘句（原文）**
1. **地方有分量**：这段文字里，这个地方本身是场景、是感受、是描写；不是顺带提到地名、过境、统计、里程。最重要的一条。
2. **选段完整**：开头结尾在合适的地方，读者不看上下文也能明白；没有截在半句话里。
3. **出处位置对**：`location`（章节、篇名）和书里一致。
4. **高亮合适**：高亮的是这个地方的名字或它在书里的叫法，不多不少。
5. **译文**（有 `text_zh` 或非英语原作的英译时）：意思对、通顺；术语和地名与地点卡一致。
6. **地点对**：点开地图看坐标和地点说明——是书里写的那个地方；原型地的说法有出处。

**场景说明（有版权的书）**
1. **具体的一刻**：谁、在这里、做了什么或看到了什么；不是情节概括、不是主题评论。
2. **没有原文措辞**：用自己的话，不模仿原句（人名地名除外）。
3. **事实对**：和 `fact_source` 对得上（章节、人物、情节）。
4. **中英一致**：`text_zh` 和 `text_en` 说的是同一件事，高亮对应。
5、6 同上（地点对；高亮合适）。

## 3. 决定

| 决定 | 含义 | 之后 |
|---|---|---|
| **通过** | 六点都没问题 | `status: "reviewed"`；网站照常显示（自译的英译标签变成“已审核”） |
| **打回** | 至少一点有问题，写原因 | `status: "rejected"`；**网站不再显示这一条**；原因记进 `docs/review-log.md`，内容包国家另写进 `packs/<国家>/REVIEW-n.md` 给产出方 |
| **小改后通过** | 只是错字、高亮差一个词、章节号写错这类 | 打回并在备注写“小改：……”，我改完直接标通过，不用回到产出方 |
| 跳过 | 拿不准 | 留在待审，备注写疑问，下次再看 |

打回原因（审核页上勾选，可多选）：

| 代码 | 原因 |
|---|---|
| `passing` | 地方没有分量（过路、统计、清单） |
| `cut` | 选段截得不好 |
| `location` | 出处章节不对 |
| `highlight` | 高亮不对 |
| `translation` | 译文有问题 |
| `place` | 地点、坐标或地点说明不对 |
| `scene-vague` | 场景说明是概括或评论，不是具体的一刻 |
| `scene-fact` | 场景说明事实不对 |
| `scene-wording` | 场景说明用了原文措辞 |
| `other` | 其他（备注里写） |

## 4. 流程

1. 打开 `review.html`。默认显示所有已开放国家的待审条目；可以按国家、摘句/场景说明、状态筛选。
2. 逐条看，按“通过”或“打回”（键盘：`A` 通过、`R` 打回、`J`/`K` 下一条/上一条）。决定先存在这个浏览器里，随时可以中断。
3. 审完一批，点“导出审核结果”，得到 `review-decisions-<日期>.json`，放进仓库的 `reviews/` 文件夹。
4. 跑 `python3 -I tools/apply_review.py reviews/review-decisions-<日期>.json`：写回数据文件（内容包国家同时写回 `packs/<国家>/lines.json`，重新导入不会丢）、追加 `docs/review-log.md`、为内容包国家生成给产出方的打回清单。然后 `node tools/validate.js <国家>`。
5. 提交、推送。

## 5. 标准从严还是从宽

演示前的目标是**每个国家打开时，前几处看到的内容都是通过的**。所以先审各国的“门面”：首页列表里排前面的区、名气大的书、朝圣地。冷门条目可以先留待审——待审条目在网站上照常显示，不打回就不会消失。
